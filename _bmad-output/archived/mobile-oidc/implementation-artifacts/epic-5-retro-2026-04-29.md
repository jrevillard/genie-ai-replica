## What Went Well

### 1. Architecture Integrity Preserved

The dual deep link mechanism defined in the architecture (custom URL scheme for OIDC, Universal Links/App Links for password reset) was implemented exactly as designed. `RedirectUriReceiverActivity` was untouched, `flutter_appauth` handles OIDC callbacks internally, and `app_links` routes non-OIDC HTTPS links to the system browser via `url_launcher`. Zero architectural drift.

### 2. Keycloak-Only Password Reset (Story 5.1)

No Flutter code changes were needed for the password reset flow. The entire flow is browser-based via Keycloak's built-in feature. This validates the architectural decision to delegate account management to Keycloak rather than implementing it in-app.

### 3. Thorough Multi-Platform Configuration (Story 5.2)

Story 5.2 touched 5 different technology stacks (nginx, Android manifest, iOS pbxproj/XCConfig, Dart, documentation) and maintained coherence across all of them. The `nginxPublicDomain` manifestPlaceholder in build.gradle, `ASSOCIATED_DOMAINS` in 12 XCConfig files, and the `$(ASSOCIATED_DOMAINS)` variable in Runner.entitlements all follow the pattern established in Epic 4.

### 4. Explicit Verification Over Assumptions

The review caught a missing cold-start link handler (`getInitialLink()`), missing error handling on stream subscription and `launchUrl`, and missing cache headers — all subtle but real bugs that would have caused issues in production. The review depth was appropriate for a multi-platform configuration story.

### 5. Documentation Quality Maintained

The deployment guide was updated with JSON structures, nginx config, platform-specific setup instructions, verification testing steps, and prominent warnings about placeholder values and iOS CDN caching. The Epic 4 commitment to "documentation stories require the same rigor as code" was honored.

## Challenges

### 1. Zero Automated Tests (Epic-Wide)

No unit tests, no integration tests. This is the third consecutive epic with zero test coverage (Epics 3, 4, 5). While Epics 4 and 5 are configuration/documentation, the `app_links` wiring in `main.dart` (stream subscription, URI parsing, browser routing) is testable Dart code that received no automated verification.

**Impact:** High. Story 6.5 (Auth Test Suite & CI) is the last story in Epic 6 and carries the entire testing burden. If 6.5 encounters blockers, the entire mobile OIDC initiative ships without automated tests.

### 2. pbxproj Manual Editing Continues (Story 5.2)

Story 5.2 added `CODE_SIGN_ENTITLEMENTS` to all 15 Runner build configs in `.pbxproj` — another round of manual editing. This was flagged as a risk in the Epic 4 retrospective with a committed action item to evaluate automation. No progress was made.

**Impact:** Medium. Each new flavor or entitlement change requires hand-editing dozens of build configs. The risk of introducing inconsistencies grows.

### 3. Deferred Items Continue to Accumulate

5 items deferred in Epic 5 (2 + 3), bringing the total across Epics 1-5 to approximately 35+ deferred items. Most are pre-existing or low-severity, but the pattern is consistent.

**Key defers:** Legacy `/password-reset` routes in `main.dart` (deferred to Epic 6), pbxproj typos, `e2e_config.dart` missing `allowInsecureConnections`.

### 4. Placeholder Values in Committed Files

Both `apple-app-site-association` and `assetlinks.json` were committed with placeholder values (`TEAM_ID_HERE`, `BUNDLE_ID_HERE`, `SHA256_FINGERPRINT_HERE`). While a `README.md` was created to guide customization, operators could deploy without realizing these need to be changed.

**Impact:** Medium. Universal Links/App Links silently fail with placeholder values — no error message, just "links open in the app instead of the browser" behavior.

### 5. Swarm Env Var Passthrough — Pattern Repeated

Story 5.1 correctly identified that `KEYCLOAK_RESET_PASSWORD` needed to be in the `keycloak-config` service `environment:` block (not `env_file`). This is the same Swarm constraint documented in Story 4.2. The pattern is now well-understood but still relies on manual verification.
