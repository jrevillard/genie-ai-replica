## What Went Well

### 1. Infrastructure Bug Discovery via E2E Tests

The Keycloak proxy chain bug (NGINX → Kong → Keycloak) had existed since the initiative's start. Only Story 6.5's E2E tests — which traverse the full proxy chain — detected it. The fix required upgrading Keycloak 26.5.6 → 26.6.1, adding Kong request-transformer plugin for X-Forwarded-Prefix, correcting NGINX X-Forwarded-Port, and removing backend `azp` validation. This validates the critical value of end-to-end testing.

### 2. Dead Code Cascade Protocol

The systematic "trace upstream after every deletion" protocol, established in Story 6.2, was applied successfully in 4/5 stories. It caught cascading references that would have caused compile errors: ChatHistoryProxy and UserProfileProxy referencing removed `accessToken` (6.1), AuthErrorWidget used by OIDC login not legacy code (6.2), orphaned UserService methods (6.3).

### 3. Zero Regressions

Despite 26 patches across 5 stories, no story broke the existing 168 tests. The incremental approach — each story verified against the previous baseline — maintained stability throughout.

### 4. Test Suite Delivery

Story 6.5 broke the 3-epic test drought (Epics 3, 4, 5 had zero automated tests). 17 new unit tests brought auth service coverage from 74.9% to 81.4%. 9 Patrol E2E tests cover all PRD integration points. CI pipeline runs automatically on MRs.

### 5. Surgical Small Stories

Stories 6.3 and 6.4 were small, focused, and completed without debug issues. The disciplined scope control — 6.3 removed exactly what was needed, 6.4 made a single security change — demonstrates that not every story needs to be complex.

## Challenges

### 1. Scope Overflow in Story 6.5

Story 6.5 was scoped as "add tests + CI." It ended up also fixing the Keycloak proxy chain infrastructure, updating NGINX/Kong/Keycloak/backend/docs/Ansible configurations, changing the `KEYCLOAK_ADDITIONAL_REALMS` format, adding ROPC automation, and creating an additional E2E test. This was **inevitable** — the infrastructure bug was only detectable through E2E tests — but it doubled the story's effort.

### 2. E2E Test Stabilization (3 days)

Stabilizing 9 Patrol E2E tests required 3 days of debugging:
- Deprecated `$.native` API → `$.platformAutomator.mobile` migration
- Android Test Orchestrator crash on long test names (path separator error)
- SecureTokenStorage pollution between tests (added clearSecureStorage() to all setUp)
- Patrol CLI worktree path bug (created patrol-wrapper.sh)
- Chrome Custom Tab not automatable from E2E (adapted test approach)

### 3. Deferred Items Continue to Accumulate

13 items deferred in Epic 6 (5+5+2+0+4), bringing the multi-epic total to ~48+ deferred items. Most are pre-existing or low-severity, but the pattern is consistent across all 6 epics. No systematic audit has been performed.

### 4. Out-of-Scope Infrastructure Fix

The Keycloak proxy chain fix touched: Keycloak upgrade, Kong plugin, NGINX config, backend keycloak-auth-service, architecture docs, docker-compose docs, docker-swarm docs, Ansible templates, env template. This was production infrastructure, not mobile code. While necessary, it blurs the boundary between mobile OIDC and platform infrastructure.
