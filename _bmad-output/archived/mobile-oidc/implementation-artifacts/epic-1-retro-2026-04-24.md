## Successes

- **Architecture solide** — 6 architecture decisions (D1-D6) respected without deviation across all 5 stories
- **Testability without mockito** — TokenStorage and AppAuth abstractions eliminated need for mockito/mocktail; InMemoryTokenStorage + constructor injection used instead
- **Zero regression record** — Test count grew from 13 to 54 without any regression
- **Consistent review discipline** — Every story received post-implementation code review; 19/19 issues fixed
- **Incremental dependency-ordered execution** — Stories 1.1→1.4 followed a clear dependency chain with no circular dependencies
- **Previous Story Intelligence** — Each story carried forward patterns, decisions, and review feedback from previous stories

## Challenges

1. **Mid-implementation architectural correction (Story 1.3a)** — Task 0 prerequisite added `realm` field to `KeycloakConfig` because OIDC discovery requires realm URL, not server root. Caught early but unplanned.
2. **flutter_appauth v11 API documentation gaps** — Nullable `accessToken` (docs claimed non-nullable), named-param-only exception constructors, `Future.microtask()` not reliably awaitable in tests.
3. **Manual E2E testing bottleneck** — Stories 1.3b and 1.4 had acceptance criteria verifiable only via manual device testing. No CI test can simulate OIDC callback flow.
4. **Android platform configuration complexity** — NDK, build-tools, Gradle flavor variant naming changes, iOS hardcoded schemes, NDK license blocking manifest verification.
