## 1. Runtime candidates

Five candidates screened against the agreed hard gates G1–G7 (§ Requirements frame); no candidate failed a gate outright, two with caveats (§2.1). Ranked order below is the weighted decision matrix, §2.3.

**1. Custom minimal tool-calling loop — RANK 1 (weighted 57.5, §2.3; verdict §2.4, REC-1 §6) — *provisional per AM-2*.** A thin agent loop GENIE owns outright behind the document-capability contract: every tool is registered explicitly by the server (the registry *is* the authorization surface — the model cannot call anything unregistered), state is whatever the loop carries in conversation scope, and streaming/citation events are shaped by us. Practitioner evidence puts the production core at ~80 lines, with failure modes living in the loop itself (tool-result ordering, unsatisfied stop conditions), not in a missing abstraction (§2.2, source [26], medium confidence). No framework to deprecate, no licence, no transitive deps. **AM-2:** the 4/5 maturity score is unimplemented-candidate screening, not proof — the ~80-line example does not cost the validation/retries/streaming/cancellation/audit integration; a GENIE implementation against the PRD's requirements is the evidence D03 needs before accepting this pick. Research verdict stands as a screening recommendation, not proof of comparative production fitness.

**2. pydantic-ai — RANK 2 (52.0; named runner-up, §2.4, REC-2 §6).** Typed Python agent framework, 2.68.0 Production/Stable, 21.2k stars, fastest release cadence in the field (100 releases in 6 months), MIT (repo-verified; PyPI licence field empty) (§1, §2.2). Tool model: typed `@tool` decorators; state: 9 durable-execution engines for multi-step workflows; OpenAI-compatible `base_url` documented; plain OTel ("any backend you already run works"); its `UsageLimits` (request limit default 50, token limits) is the only source-verified budget story covering loop turns *and* tokens. Python-only. Research verdict: runner-up — wins instead if typed framework support or durable multi-step execution is valued over loop ownership; also the cheapest migration target from the custom loop. Designated fallback with a ≤1-day swap-in exit test.

**3. OpenAI Agents SDK — RANK 3 (44.5, §2.3).** OpenAI's multi-agent SDK, dual-language (Python 30.7k stars / JS), MIT, 28 releases in 6 months, vendor-backed and active (§1). Function-tool model, documented cancellation (`cancel()`, `after_turn`), streaming events (`raw_response_event`, tool lifecycle). Carries **two sovereignty caveats** (§2.2): tracing is enabled by default in server runtimes and exports to OpenAI cloud using the model key *even when baseURL points elsewhere* — `setTracingDisabled(true)` mandatory for GENIE; and Chat-Completions compatibility mode "silently drops" non-text tool outputs. Tool-delta streaming in CC mode unverified (OQ-1). Research verdict: best team fit (Node+Python) but penalized on sovereign observability (2/5).

**4. LangGraph — RANK 4 (43.8, §2.3).** Graph-based agent orchestration, Production/Stable, strongest vitality (45.0k stars, 71 releases in 6 months), MIT (§1). Tool model: prebuilt ToolNode; state/session model: checkpointer saving state at every superstep keyed by `thread_id` — core machinery SC-01 does not need. **AM-3:** node-scoped cooperative time controls exist (`TimeoutPolicy.run_timeout`/`idle_timeout`, node-attempt scope, asyncio-cancellation-based; `step_timeout` in the engine) — the original "no time/token budget" overstated; correct is "no complete end-to-end request/token budget". Checkpointer optional (`compile` defaults to None); distinguish the `langchain-core` dependency from operating a persistence backend. A 12-project consultancy retrospective rates its debugging story "still worse than a custom loop" (§2.2, [27], medium). Research verdict: strongest maturity but heaviest and least reversible of the field (exit cost 2.5/5).

**5. DeepSeek Harness (DSH) — RANK 5 (27.5, §2.3; REC-8 §6) — *ranking provisional per AM-1*.** **AM-1 (verified):** DSH ships an SDK family driving a complete Harness runtime from another process over JSON-RPC on stdio — TS client spawning `dsh` as a subprocess, Python SDK with a bundled runtime (`sdk-minimal` profile) — so "workstation, not embeddable" was factually wrong; the integration mode is an **SDK-driven subprocess**. The original rank-5 verdict rested partly on that false premise. Still valid: developer preview (repo 2026-08-13), explicit "not production-ready, no security audit" SAFETY notice, zero evidenced adoption, vLLM untested against it, GitHub Discussions as only support surface, niche Cordis DI dependency. Genuine strengths unchanged: clean `ToolDefinition` split; `pi-ai` adapter to OpenAI-compatible endpoints via providers YAML. MIT (repo + npm verified). Verdict pending re-assessment: the subprocess integration mode (lifecycle, isolation, resource cost, availability in the published version) is **unassessed** — assess before treating the ranking as settled. Borrow the `ToolDefinition` split as a pattern regardless.

**Wildcards and field context (§1, §2.1 cuts):** Agno (43.2k stars, Apache-2.0) — credible wildcard missed by the initial list, parked (vendor-cloud-first positioning); Google ADK (22.2k stars, Apache-2.0) — parked for the same reason; Mastra (29.5k stars, TS) — **cut, licence-unverified** (NOASSERTION pending manual LICENSE read — AM-5: unverified, not incompatible); AWS Strands — unscreened (repo not located, rate-limited); smolagents — 30.4k stars but release train stalled (1 release in 6 months); AutoGen — superseded by Microsoft Agent Framework 1.0 (2026-04-03, Semantic Kernel + AutoGen merger). None of these was scored.

## 2. Architecture patterns

- **Agentic RAG = retrieval inside a model-directed tool loop (§1, [10]).** The 2026 pattern set: four primitives (decision-to-retrieve, query transformation/decomposition, iterative retrieval, self-check) and five recurring production patterns (query rewrite/decompose, multi-hop with state, tool routing across retrievers, faithfulness self-check on the draft, re-retrieve-until-supported under a step budget). Production bounds reported: 1–6 retrievals per turn (capped 4–6), 3–8 LLM calls per turn. Single-shot RAG remains the correct choice for single-document lookup; agentic wins on multi-hop and ambiguous queries.
- **Workflows vs agents — start simple, with teeth (§3, [1]).** Anthropic's taxonomy distinguishes predefined paths (workflows) from model-directed loops (agents) and mandates explicit stopping conditions plus environmental ground truth at each step. SC-01 as specced (one agent, small toolset, step budget) is exactly the rung above single-shot RAG the literature endorses for multi-hop queries.
- **Per-request authorization — converged pattern (§3, [8][11]; claim verified).** Two independent publishers agree: effective permissions of an LLM operation = **intersection of (LLM, user, task) permissions**; agents acting for a human use *impersonation/delegated-access* semantics — the user is the actor, neither party gains permissions. Enforcement belongs in the tool executor with per-request identity.
- **Citation enforcement is mechanical, not rhetorical (§3, [9]).** A grounding instruction took invented answers from 4/4 to 0/4 on unanswerable questions, but *adding* a citation instruction made things worse — the model attached citations to invented facts. Enforcement = automated verification that each cited source supports its claim, over structured tool results carrying stable source ids, plus a refusal path; eval sets must contain unanswerable questions.
- **Bounded execution (§3, [1][30]).** Explicit stopping conditions are the pattern-literature mandate; production failure accounts corroborate (infinite loops, call counts 2–3→10–15). No framework documents client-disconnect→loop→vLLM cancellation propagation — it must be designed in-house.
- **Client stream events converging, tool layer standardizing (§3, [12][13][14]).** AG-UI 1.0 formalizes the client event taxonomy (run lifecycle, text deltas, tool-call lifecycle, state); MCP standardizes the tool layer (server-side enforcement, human-in-the-loop SHOULDs), not the client stream. No ratified client-stream standard; adoption at scale unread (OQ-4).

**Recommended pattern (§2.4, REC-1, REC-7):** SC-01 as a custom minimal tool-calling loop over a small registered retrieval toolset, with a step budget — i.e. the agent-loop-over-retrieval-tools pattern, one agent — because it matches the endorsed rung for multi-hop QA, keeps reversibility maximal in a field whose pattern half-life is months, and because the hard parts (citations, authz, cancellation, vLLM quirks) are GENIE's under every option (§5).

## 3. Sovereignty / open-source findings

- **Sovereignty is attacked by defaults, not features (§5.2).** The field's one documented sovereignty failure: OpenAI Agents SDK ships telemetry to OpenAI cloud **by default**, keyed on the same credential as a self-hosted `baseURL`, in both JS server runtimes and Python (§2.2, [4][5]). Research position: audit *defaults* as gates, not just capabilities — a PRD-level requirement, not a one-off flag.
- **Model-endpoint independence: all five candidates pass G3 on paper** via OpenAI-compatible mechanisms (§2.1): custom loop (we own the client, native), pydantic-ai (`OpenAIProvider(base_url=…)` documented), Agents SDK (`set_default_openai_api`/`OpenAIChatCompletionsModel`), LangGraph (`ChatOpenAI(base_url=…)`), DSH (shipped `pi-ai` adapter). Caveat: DSH's mechanism is verified but never tested against vLLM specifically (§2.2); Agents SDK CC mode silently drops non-text tool outputs (sovereignty + correctness caveat, §2.2).
- **Licence posture:** all scored candidates MIT — Apache-2.0-compatible (§2.1). Traps recorded: LangGraph "standalone" still hard-depends on `langchain-core` (§2.2, [16]); pydantic-ai's PyPI licence field is empty (MIT verified only at repo level, §2.1); **Mastra cut as licence-unverified** (NOASSERTION with an unread LICENSE — AM-5: unverified, *not* an incompatibility finding; never count failed retrieval as incompatibility); Strands unscreened. Wildcards Agno and Google ADK are Apache-2.0 but parked for vendor-cloud-first positioning (§2.1).
- **Framework churn as a sovereignty-adjacent risk (§1, §5.1):** Anthropic's own agent guidance was partially superseded within a year; the runtime field restructured around vendor stacks in 2026 (AutoGen→Microsoft Agent Framework). Vendor-ecosystem stacks (OpenAI Agents SDK, LangGraph, ADK) map to their clouds/telemetry stacks — a thin, replaceable agent layer behind a stable contract is the sovereignty-preserving posture.

## 4. Risks and open concerns

- **The "custom loop is enough" pick rests on medium-confidence practitioner evidence** ([26][27]) plus the structural argument — no public head-to-head exists at GENIE's scale (§ Executive summary caveat, §2.4). GENIE would own the plumbing frameworks ship: retries, schema validation, tool-delta streaming quirks.
- **Node-vs-Python placement: no public evidence at all** (§4) — an architecture decision from team constraints, not research (OQ-6).
- **Cancellation and client-disconnect propagation are undocumented everywhere** (§3, OQ-7): no framework documents disconnect→loop→vLLM; must be designed and tested in-house (E01/E02 must cover it). Breaking an Agents SDK stream does NOT stop its run ([3]).
- **vLLM tool-calling prerequisites are version- and mode-scoped (§4, [2], REC-6; corrected by AM-4):** vLLM v0.29.0 (compose-pinned) supports named and `required` `tool_choice` **by default** via the structured-outputs backend — no parser flag needed for those modes; `--enable-auto-tool-choice` + a model-family parser is the prerequisite for **automatic** calling. Without `strict` schemas malformed tool-call markup can leak into responses (auto mode); first named/required call pays seconds of FSM-compile latency (structured-outputs path); hf/checkpoint parsers emit tool calls whole and drop non-parsing calls with no documented error path. Requirement: version × model × parser × tool-choice-mode × schema-strictness × streaming compatibility matrix, validated against the deployed combination in V06.
- **DSH-specific:** 3-month-old developer preview, no security audit, zero evidenced adoption, embeddability premise corrected per AM-1 (SDK subprocess mode exists; operational assessment outstanding), DSH↔vLLM compatibility untested (§2.2, §1); highest-value gap flagged in the memlog as "decide before scoring DSH" (resolved as a mechanism-level pass, §2.2).
- **Evidence-quality caveat (frontmatter + § Executive summary):** claims tally 2 verified / 22 unverified / 1 overturned. Notably the Adaline cost/latency numbers (40%/35%) are vendor-reported without methodology — direction plausible, numbers not evidence (§4); the 30–45%/25–40% secondary was drift (overturned).
- **Open questions OQ-1..OQ-7 (§7):** tool-delta streaming in Agents-SDK CC mode / DSH pi-ai against the deployed vLLM parser (live smoke test); LangGraph cancellation semantics; Strands repo+licence and Mastra LICENSE text (rate-limit blocked); AG-UI production adoption at scale (REC-7 is pattern-level, not dependency-level); IETF draft-klrc-aiagent-auth continuation (the -00 expired 2026-09-03 — check for -01 before citing as direction, §3); plus OQ-6/OQ-7 above.
- **Freshness (§ Staleness map):** none stale at completion, but the compat/version class re-checks **2026-12-01** — every one of those claims gates REC-1/REC-2/REC-6 and "moves within weeks".

## 5. PRD-ready conclusions

Researched positions (not decisions), each with its research anchor:

- Build SC-01 as a custom minimal tool-calling loop behind the GENIE document-capability contract, in a new OPEA-free service — do not adopt DSH as a dependency, do not adopt a heavyweight framework for the first iteration. (§2.4 verdict, REC-1 §6)
- Keep pydantic-ai as the designated runner-up/fallback (typed tools, `UsageLimits`, OTel, Python); write a reversibility requirement with a ≤1-day swap-in exit test. (§2.4, REC-2 §6)
- Bounded execution must be written as explicit requirements — step cap, wall-clock, per-run token budget, evidence-volume cap, cancellation propagated from client disconnect — because no framework supplies it completely. (REC-3 §6, §3)
- Per-request authorization follows the converged intersection model: effective permissions = user ∩ task over the registered toolset, the user is the actor, enforcement in the tool executor, model-generated arguments never widen access. (§3, REC-4 §6; claim verified by two independent sources)
- Citations need mechanical verification over structured tool results with stable source ids, a grounding sentence in the system prompt, a refusal path, and unanswerable questions in the eval sets — prompt-level citation instructions alone made invention worse. (§3, REC-5 §6)
- vLLM operational prerequisites are binding: pin the parser family per served model, enforce strict tool calling, budget first-call FSM latency, test tool-delta streaming against the deployed parser. (§4, REC-6 §6)
- Adopt the AG-UI event taxonomy as the internal event shape (pattern-level, not a dependency) mapped onto the existing SSE contract. (§3, REC-7 §6)
- Record DSH's revisit trigger: stable non-preview release + embeddable server mode + security audit; borrow its `ToolDefinition` split as the G4 pattern now. (§2.2, REC-8 §6)
- Sovereignty must be gated on defaults, not capabilities: audit every runtime/dependency for default telemetry, default cloud export, and licence posture (LangGraph's `langchain-core` hard dep, Mastra's unresolved licence) before adoption. (§5.2, §2.1)
- Agentic scope: the agentic path targets multi-hop and ambiguous queries; single-shot RAG stays the correct path for single-document lookup — the PRD should scope the agentic feature accordingly (production bounds: retrievals capped 4–6 per turn, 3–8 LLM calls per turn). (§1, §3)
