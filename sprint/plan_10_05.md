## Task 0 — Reranker-failure resilience (K.0, PRIORITY)

Live finding 10-05 (agriconnect.site): transient CUDA OOM in the TEI reranker
(`text_embeddings_core::infer`, tensor clone) → Python reranker re-raises →
FastAPI 500 with a **text/plain** body (no exception handler registered,
genieai_reranking_microservice.py:111-122) → chatqna orchestrator's
`response.json()` ContentTypeError decoding that body → chatqna 500 → UI
"chatqna returned 500". Exactly 2 hits in 3h, 9s apart, self-recovered;
on-box rag-tuning.json pristine (v1/seed); reranker logs show the K wiring
working identically to pre-deploy (slice/3/0.75, ~30ms reranks before and
after). **K.1–K.3 exonerated.**

Defect class: an OPTIONAL quality stage (the reranker) failing transiently
kills the whole query — no retry, no degrade, no honest error. Secondary:
the reranker emits text/plain error bodies, which is what crashes the
orchestrator's JSON decode (and masks the informative error text).

VRAM context: one GPU hosts vLLM + TEI embedding + TEI reranker; a 20-doc
rerank of long chunks landing at vLLM KV-cache peak is the high-water mark
(admin mitigation exists: retrievalK 20→10 in the panel; deploy-side vLLM
gpu_memory_utilization nudge).

Full BMAD loop when scheduled (spec → build → review → gates → deploy →
live test).

Port Vladimir's mechanism, adapted to our stack, attributed in code + spec:
- Bind-mounted `configs/*.json` under a shared path (backend writes, chatqna/
  retriever/reranker read); env var path override per service (his
  `LLM_MODELS_CONFIG` / `RAG_TUNING_CONFIG` pattern).
- mtime-guarded per-request re-read (no restart), validated admin writes,
  defaults-merge on read, audit stamps (`updatedAt`/`updatedBy`).

  are the SEED only. Loud degradation: missing/invalid file = warn + documented
  defaults, never silent (plan.md:21).
- Preflight coherence: assert file parses + required keys at deploy preflight
  (B2 pattern) so a bad edit can't ship.
