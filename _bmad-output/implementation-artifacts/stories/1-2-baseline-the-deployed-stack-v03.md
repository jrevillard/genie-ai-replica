## Intent

**Problem:** E01 (Epic 4) proves the OPEA-free path preserves the legacy behavior by comparing it against a reference. The repository declares what the stack *should* run; the deployment is the only place the truth lives — its image digests, the model ids the GPU node actually serves, the retrieval knobs the running pods carry, its topology. Nothing records them today, so an equivalence suite would measure against an assumption instead of against the system that serves traffic.

**Approach:** A read-only capture reads the live deployment and the repository's chart source, reconciles them value by value, and renders a dated baseline record — digests, models, retrieval configuration, topology — in which every difference carries a disposition. The capture is re-runnable, so the record can be refreshed when the deployment moves, and re-captured on another venue when one is designated.

## Boundaries & Constraints

**Always:** read-only against the cluster and the registries; no secret value ever reaches the record; every difference carries a disposition or the capture fails loudly; the record names the deployment it describes and the command that reproduces it.

**Never:** never create, patch or delete anything in the cluster; never update the running stack (the venue update is a separate procedure); never pick the E01 venue — PRD §13-1 stays open, and this story records a named live deployment instead; never widen the comparison past the retrieval configuration, the model ids and the topology the acceptance criteria name.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|---|---|---|---|
| Capture a running namespace | a namespace with the chart installed | the record lists every workload with its running digest, the four model roles, the retrieval configuration and the topology | the capture exits with the reason and writes no record |
| Chart-value knob | a variable the chart renders from a values leaf | the row compares chart default, overlay override and deployed value | a difference is listed with its disposition |
| Template-rendered knob | a variable the template renders from a literal or a helper | the row is marked TEMPLATE and never compared | none — it is not a difference |
| Difference without a disposition | a deployed value that differs from the source and has no known disposition | listed as UNRESOLVED | the capture exits 2 |
| Secret-backed variable | a variable whose value comes from a secret or a downward API | the record shows the reference, never the value | none |
| Injected service-discovery variables | the `*_SERVICE_HOST` / `*_PORT_*` entries Kubernetes adds | skipped | none |

## Implementation Notes

- The baseline venue is the shared k3s `genieai` namespace (chart 0.2.177, external GPU model tier). The record's release revision follows the deployment: the capture that ships was taken at release `genieai.v50`, after the 2026-11-18 repoint settled. PRD §13-1 (which deployment hosts the first end-to-end validation) stays open: the capture takes the namespace as an argument, so designating a venue is a re-run, not a rewrite.
- The record reconciles the deployment against **the chart source in this repository** (its `values.yaml` defaults plus the overlay the release carries). Whether that source is the chart the running release was rendered from is a separate question: the chart-identity attestation that answers it exceeded the acceptance criteria, was trimmed twice on the operator's ruling, and is now story 1.2b (#1998).
- The comparison layers are chart default → overlay override → running pod, and they stay three distinct columns. A difference against the *effective* value (default + override) is a discrepancy; a difference against the chart default alone is not.
- `imageID` is the digest of the pulled image **index** (calibrated against the digest-pinned Envoy image: the pod's `imageID` equals the tag's index digest, not its amd64 child). The index digest is not a content identity — it moves on every re-push (the attestation changes the index, not the image) — so the verdict compares the **amd64 child digest**, the content identity, and the record carries both. The registry still serves the running index digests; what moved is the CONTENT behind the mutable `main` tag: the deployments run an earlier build than the tag now points at. The record states which of the two it is, per image.
- The chart templates are parsed, never guessed: the mapping from a values leaf to an environment variable exists only in the templates. A variable the parse cannot resolve is reported as TEMPLATE (rendered from a literal or a helper), never silently compared. The values the chart *computes* — the GPU endpoint family and the public origin, the two venue-specific values a cross-venue baseline exists to pin — are derived exactly as the chart's helpers derive them and compared like any other value.
- The capture is read-only. It creates, patches and deletes nothing, and a secret value never reaches the record: a secret-backed variable is shown as its reference, and the model endpoints are probed with the TLS posture of the workload that declares the endpoint.
