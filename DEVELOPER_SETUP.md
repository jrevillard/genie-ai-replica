# Amina — Developer Setup

How to get from a fresh `git clone` to a fully-working local Amina with every
demo account and dataset we reference in the docs.

## 1. Prereqs

* Docker Desktop (with WSL2 backend on Windows)
* Python 3.11+ on your PATH (for running the seed scripts from the host)
* Node 20+ if you want to run the frontend dev server

## 2. Bring up the stack

From the repo root:

```bash
docker compose \
  -f haystack-stack/docker-compose.yml \
  -f haystack-stack/docker-compose.override.yml \
  -f haystack-stack/docker-compose.meta-channels.yml \
  -f haystack-stack/docker-compose.inbox.yml \
  -f haystack-stack/docker-compose.resilience.yml \
  -f haystack-stack/docker-compose.gap-closers.yml \
  -f haystack-stack/docker-compose.dhis2-history.yml \
  -f haystack-stack/docker-compose.oauth.yml \
  up -d
```

Wait ~30s for ArcadeDB + Redis + Haystack to become healthy:

```bash
curl -sf http://localhost:8000/health
```

## 3. Seed demo accounts + data

The live `haystack-stack/data/` directory is **intentionally not in git** (PHI
risk + multi-hundred-MB transaction logs). The seed scripts reproduce every
login deterministically — passwords, PINs, ids, and relationships are all
derived from fixed strings, not random.

Run them once after the stack is healthy:

```bash
cd haystack-stack/haystack-chatqna

# (a) Admin-patient account
python scripts/seed_admin_patient.py
#   → admin@demo.aminacare / Amina2026  (JWT role = admin)

# (b) 8 caregivers with fixed PINs 1111..8888
python scripts/seed_caregivers.py
python scripts/reset_caregiver_pins.py
#   → phones +2203110001 … +2203110008, PINs 1111 … 8888

# (c) 10 demo patients (5 basic + 5 advanced clinical scenarios)
python scripts/seed_demo_patients.py
python scripts/seed_demo_patients_advanced.py

# (d) Caregiver-linked patients (Dado Badjie + Seedy Mendy)
python scripts/seed_dado_seedy.py

# (e) Supply ledger + dual-path ledger demo data for admin-patient
python scripts/seed_admin_patient_ledgers.py
```

## 4. Ingest the WHO-PEN knowledge base (optional but recommended)

The `_recovery/docs/` directory contains 5.5 MB of public clinical references
(WHO PEN protocols 1–5, Gambia NCD Strategy, KDIGO CKD, etc.). To make them
available to Amina's RAG pipeline on your local instance:

```bash
cd haystack-stack/haystack-chatqna
python scripts/bulk_ingest_chunks.py --docs-dir ../_recovery/docs
```

Skip this if you only want to exercise the CRUD / escalation flows — the
backend starts and runs fine without the corpus ingested, the chat replies
will just be more generic.

## 5. Frontend dev server

```bash
cd components/frontend
npm install
npm run dev
```

Open `http://localhost:5173`. The hash router boots you to `#/home`; follow
the Sign-In tabs or use the pre-seeded accounts below.

## 7. Runtime data paths that are intentionally gitignored

| Path | What | How to recreate |
|---|---|---|
| `haystack-stack/data/` | ArcadeDB + Redis live state | Run steps 3 + 4 above |
| `haystack-stack/_recovery/docker/*.vhdx` | Docker Desktop VM disk | Docker rebuilds on first boot |
| `haystack-stack/scribe_audio/` | Voice recordings (PHI) | Generated by `/scribe/record` interactions |
| `haystack-stack/inbox_files/` | Uploaded patient files (PHI) | Generated by inbox capture |
| `haystack-stack/backups/` | Scheduled backup zips | Backup job re-creates |

```bash

python _role_escalation_test.py   # JWT + body-role matrix

python _village_roles_test.py     # Village pillar / note gate
python _scout_roles_test.py       # Scout Alkalo-only + notifications
python _bantaba_roles_test.py     # Per-patient circles + add-member requests
python _caregiver_notify_test.py  # Inbox + chat + emergency fanout
```
