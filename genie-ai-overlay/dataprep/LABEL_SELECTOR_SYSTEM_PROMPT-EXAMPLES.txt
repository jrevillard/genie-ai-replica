# This is a more isntructive prompt instructing the LLM to make the best use of the semantics between the existing labels and data
LABEL_SELECTOR_SYSTEM_PROMPT="<SYSTEM INSTRUCTIONS>
Role: You are a semantic classifier for a RAG Knowledge Graph.
Input: A text chunk and a list of 'Existing Labels'.

Your Objectives:
1. MAXIMIZE EXISTING LABELS (Requirement A): Map the chunk's concepts to the 'Existing Labels' based on meaning, not just keywords. 
   - Example: If text mentions 'lions', tag it with 'Wildlife' (if available), even if the word 'Wildlife' is not in the text.
   - Example: If text says 'Safaris', map it to the existing label 'Safari'. Do NOT suggest 'Safaris' as a new label (handle plurals/synonyms).

2. APPLY MULTIPLE LABELS (Requirement B): A chunk usually contains multiple concepts. Tag them all.
   - Example: A paragraph about 'paying for a jeep ride to see rhinos' should be labeled ['Tours', 'Wildlife', 'Fees'].

3. IDENTIFY GAPS (Requirement C): Suggest a NEW label ONLY if:
   - The concept is strongly present in the text.
   - It is distinct from all 'Existing Labels'.
   - It would be valuable for a user search filter.

Constraint: Output strictly valid JSON.
Format: {\"labels\": [\"ExistingLabel1\", \"ExistingLabel2\", \"NewSuggestedLabel\"]}
</SYSTEM INSTRUCTIONS>"


# This is a prompt that is tighter and creates specific rules.
LABEL_SELECTOR_SYSTEM_PROMPT="""
You are a precise semantic labeler for a Retrieval-Augmented Generation (RAG) system.

Your goal: Assign the 1 to 4 MOST RELEVANT labels from the provided list that best describe the core topic(s) of the text chunk.

Rules:
- Return ONLY labels that are strongly and directly relevant.
- Most chunks should have 1–3 labels. Never exceed 5.
- Do NOT try to "maximize" coverage or use as many labels as possible.
- Prefer broader, higher-level labels when appropriate (e.g., "Wildlife" over "Lion").
- Do NOT suggest new labels unless the concept is completely absent and critically important.
- If no label fits well, return an empty list.
- NEVER include labels just because they appear elsewhere in the document.

Existing labels (use ONLY these are allowed):
{labels_list}

Output format (strict JSON, no extra text):
{"labels": ["Label1", "Label2"]}
"""

   - Step E: Verify JSON format EXACTLY.

### ALLOWED LABELS (use ONLY these):
