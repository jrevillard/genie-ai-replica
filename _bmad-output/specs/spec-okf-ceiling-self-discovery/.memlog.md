- (decision) Ruling (David 2026-11-15): SELF-DISCOVERY — okf-server derives the concept-document ceiling from the SAME /v1/models window dataprep reads, TTL-cached; not a parallel static knob and not dataprep publishing the number.
- (decision) okf-server keeps ONE ceiling authority: services/concept-ceiling.js stays the single reader all three enforcement paths (import, editor save, publish gate) call; discovery feeds it instead of bypassing it.
- (decision) Discovery reads VLLM_ENDPOINT + /v1/models (the endpoint dataprep reads) and honors the SAME operator lever DATAPREP_MAX_MODEL_LEN (0 = discover, >0 = stated window); NOT okf-server's own judge base.
- (decision) Cache shape: stale-while-revalidate TTL (house pattern: smoke harness serviceToken) — the discovery probe is network I/O and never blocks the ingest/save hot path.
- (decision) Fallback ladder (deliberate divergence from dataprep semantics): explicit OKF_MAX_CONCEPT_DOC_CHARS pin > last-known-good derived ceiling > static default 250000 with loud WARN. dataprep's DERIVE_FALLBACK_WINDOW=2048 fail-closed guess is safe for generation (raw-chunk fallback) but a guess-derived WRITE ceiling would refuse nearly every import during an endpoint blip — the write ceiling fails conservative-but-usable.
- (decision) Mirrored-constant drift guard: okf-server mirrors the formula constants (CHARS_PER_TOKEN=4, DATAPREP_CONTEXTUAL_MAX_TOKENS, batch size, prompt/scaffold lengths); a config-validator check pins okf-server's mirrored constants against dataprep's python source (validator-parses-source precedent exists), so the two-derivations drift #1588 names cannot happen silently.
- (constraint) The ceiling must keep "over the ceiling" ⇔ "document context will be truncated" the same condition — the whole point of the shared number (concept-ceiling.js header, plan §4).
- (constraint) No new required env vars; OKF_MAX_CONCEPT_DOC_CHARS remains the operator override; env/env.j2 docs move from "keep the literal in step by hand" to "unset = derived; set = pin" (#1588 operator burden ends).
- (constraint) Refusal messages keep naming the ceiling SOURCE (discovered-from-window / operator pin / static default) so a curator knows which lever moves CONCEPT_TOO_LARGE.
- (constraint) Per the docs-merge-with-code rule: SPEC + story artifacts ride the #1205 code MR, never a document-only MR.
- (capability) CAP-1 Window discovery client: intent — okf-server discovers the serving-model context window from the deployment LLM endpoint (/v1/models), honoring DATAPREP_MAX_MODEL_LEN as the operator override, cached stale-while-revalidate so enforcement paths never do blocking network I/O; success — a deployment whose endpoint serves max_model_len=X gets ceilings derived from X within one TTL of boot; an unreachable endpoint serves the last-known-good or static default with a WARN naming the failure; a stated DATAPREP_MAX_MODEL_LEN overrides discovery without any request.
- (capability) CAP-2 Derived ceiling with fallback ladder: intent — concept-ceiling.js derives the ceiling from the discovered window using dataprep's formula (prompt/batch/output/scaffold terms, CHARS_PER_TOKEN=4) so "over the ceiling" and "context truncates" stay the same condition on ANY window; success — 2048-token deployments get a proportionally small ceiling, 65536 deployments get ~219700 (matching the 2026-11-06 measurement within tolerance), the explicit env pin wins uncapped, and every refusal names the ceiling's source.
- (capability) CAP-3 Drift guard + deployment truth: intent — a config-validator pins okf-server's mirrored formula constants against dataprep's python source, and the deployment docs/env templates state "unset = derived; set = pin"; success — editing a dataprep constant without its mirror fails the validator in CI, and no config-validator check can contradict a runtime-discovered number (#1588's by-hand burden ends).
- (capability) CAP-4 Live proof: intent — the smoke harness proves the derived ceiling matches dataprep's derived budget for the same window within the formula's tolerance, and proves the ladder (pin > derived > default) on the live build; success — the smoke leg runs green on the local build with the deployed endpoint and both ceiling sources are visible in the smoke output.
- (non-goal) dataprep's derivation itself does not change (this work reads its discovery contract, it does not refactor it).
- (non-goal) The doc_level budget (DATAPREP_CONTEXTUAL_DOC_BUDGET_DOC_LEVEL) keeps its own semantics — out of scope.
- (non-goal) Map-Reduce-style hierarchical summarization for over-budget documents stays a dataprep future — truncation semantics unchanged here.
- (non-goal) No UI change: CONCEPT_TOO_LARGE surfaces keep their current shape; only the message text gains the ceiling source.
- (question) TTL value for the discovery cache (proposal: 300s, matching the smoke serviceToken cadence and okf-server's existing posture TTL of 5 min) — confirm at story time.
- (question) On remote-GPU deployments okf-server must reach VLLM_ENDPOINT (the GPU node /llm) — confirm the network path is already open (okf-server calls the judge base there; VLLM_ENDPOINT itself is emitted in env.j2 §18) at implementation time.
