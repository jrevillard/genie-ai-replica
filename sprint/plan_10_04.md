## Task 1 — Sesotho-mode answers differ badly from English (J.1)

**Symptom (Adem):** switching to Sesotho mode produces very different — and much
worse — answers than the same conversation in English mode.

**Context from the sprint (verified earlier, do not re-litigate):**
- Epic G (DEC-26) established the contract: ST sessions follow the same rules as
  EN — the answer is produced in English (English-response rule for every session)
  and the SETTLED answer is translated to Sesotho at end-of-stream via the
  `nllb-translate` sidecar. Live-proven 10-01 with the empty-corpus refusal.
- NOW the corpus is real (H-ingest + Epic I tuning): grounded answers flow. The
  ST degradation with a REAL corpus points at the retrieval/grounding leg, not the
  translation leg — e.g. retrieval running on the raw ST question against an
  English corpus (the locale propagation from G.2a feeds `language`; how the
  QUESTION is handled per-locale is the thing to trace: is the ST question
  translated to EN before retrieval, or retrieved as-is?).
- Starting hypothesis (UNVERIFIED — spec recon must confirm from code + Adem's
  samples): the ST question reaches the retriever untranslated → weak/no chunk
  matches → ungrounded generic answers, while EN mode retrieves fine. The
  langdetect path exists in chatqna (:2794-2830) with known ST misdetections
  ('sk'/'fi' — the 10-01 finding).
- Adem brings: concrete paired transcripts (same question, EN vs ST) at kickoff.

## Task 2 — Landing-page button chats always "no info" (J.2)

**Symptom (Adem):** starting a conversation via the buttons on the main page
(after login) always answers "no information on this", while typing the same
question manually works.

**Starting pointers (from quick recon 10-04):**
- Landing/main page = `DashboardView.vue` → renders `ChatBotComponent` (the chat
  IS the same component; the difference must be in what the button sends).
- Candidates to trace: the starter/FAQ buttons' payload vs a typed message —
  check `frequentlyAskedQuestions` (RightSideBarComponent renders them; what does
  CLICKING one send — does it route through sendMessage with the same
  locale/context/session payload? does it hit the CLASSIC non-stream path while
  typed messages use streaming? does it carry different labels/language?), and
  whether the canned question text genuinely matches corpus content.
- I.4 freshly landed (d84e62d4): sidebar/confidence now work — use them as
  diagnostics (does the button-chat show 0 docs while the typed one shows docs?
  That would localize the break to retrieval-input shaping, not the answer leg).
- Honest answer check: with a small corpus, some canned questions may truthfully
  have no info — verify with a question KNOWN to be answerable before calling it
  a bug.
