### B. Process lessons

**B1. 7-1 needed 3 review-pass commits** (commits `2b18260e0`, `c360a2ab0`, `b4d2b4ab6`).
Root cause: logger.js is a hot-path file with many dependents. Each pass surfaced a different concern: AD-14 ref scrub, `isCombinedRotate` symmetry, registry 429 retry. Not a defect — evidence the review loop is working — but pattern worth noting: complex hub files benefit from earlier extra review passes.

**B2. SPEC.md status never advanced past `in-progress`** (`_bmad-output/specs/spec-admin-logs-victorialogs-migration/SPEC.md:3`).
Even though every story in the spec is `done` and every epic merged. Closes-with-no-closure state. **Action item A1**.

**B3. Sprint-status rewrite churn** (observed across all 7 epics).
Orchestrator's sprint-status-sync agent rewrites `sprint-status.yaml` with 2-space indented layout + story-key renames (e.g. `1-1-docker-compose-vl-collector-always-on-no-profile: done` vs original `1-1-docker-compose-vl-collector-profiles-core: done`). Each sync overwrites human canonical form. Lesson: human edits to sprint-status should be committed BEFORE the next orchestrator cycle, else orchestrator overwrites them. (See also commit `47a8c374c` for one such correction cycle.)

**B4. Workflow-tool bugs required ~14 commits** during PRD execution (`bmad-prd-orchestrate.js` + `bmad-build-converge.js`).
Root causes seen: TDZ on `const` helpers (c474a3bed), nested-quote JSON schema (775c4f166), duplicate `let parsed` (cfc778aeb), backtick-in-template parse error (85d4dec0b, 888861f1d), `<stderr>` placeholder token (8480… etc), `&gt;` HTML entity in template. Pattern: workflow scripts use template strings containing shell-style backticks; need stricter escaping review before commit. Process lesson: lint workflow scripts at the same level as production code.

**B5. Manual recovery path used for 6-2** (commit `de07e910f`).
Build agent succeeded internally (`skillCompleted:true`) but wrapper reported `claude -p exit 1` because of `[1m]` model-id parse error in stderr noise. Required user-driven `git push` + manual MR !378 creation. Recovery worked but bypasses orchestrator auto-merge. Lesson: orchestrator should distinguish "subagent internal success" from "wrapper exit code" before declaring launch_failed.
