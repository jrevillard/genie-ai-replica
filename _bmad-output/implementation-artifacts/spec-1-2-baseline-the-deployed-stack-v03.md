## Intent

**Problem:** E01 (Epic 4) proves the OPEA-free path preserves the legacy behavior by comparing it against a reference. The repository declares what the stack *should* run; the deployment is the only place the truth lives — its image digests, the model ids the GPU node actually serves, the retrieval knobs the running pods carry, its topology. Nothing records them today, so an equivalence suite would measure against an assumption instead of against the system that serves traffic.

**Approach:** A read-only capture reads the live deployment and the repository's chart source, reconciles them value by value, and renders a dated baseline record — digests, models, retrieval configuration, topology — in which every difference carries a disposition. The capture is re-runnable, so the record can be refreshed when the deployment moves, and re-captured on another venue when one is designated.

## Boundaries & Constraints

**Always:** read-only against the cluster and the registries; no secret value ever reaches the record; every difference carries a disposition or the capture fails loudly; the record names the deployment it describes and the command that reproduces it.

**Never:** never create, patch or delete anything in the cluster; never update the running stack (the venue update is a separate procedure); never pick the E01 venue — PRD §13-1 stays open, and this story records a named live deployment instead; never widen the comparison past the retrieval configuration, the model ids and the topology the acceptance criteria name.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|---|---|---|---|
| Capture a running namespace | a namespace with the chart installed | the record lists every workload with its running digest, the four model roles, the retrieval configuration and the topology | the capture exits with the reason and writes no record |
| Chart-value knob | a variable the chart renders from a values leaf | the row compares chart default, overlay override and deployed value | a difference is listed with its disposition |
| Template-rendered knob | a variable the template renders from a literal or a helper | the row is marked TEMPLATE and never compared | none — it is not a difference |
| Difference without a disposition | a deployed value that differs from the source and has no known disposition | listed as UNRESOLVED | the capture exits 2 |
| Secret-backed variable | a variable whose value comes from a secret or a downward API | the record shows the reference, never the value | none |
| Injected service-discovery variables | the `*_SERVICE_HOST` / `*_PORT_*` entries Kubernetes adds | skipped | none |

## Code Map

- `scripts/baseline/capture-deployed-baseline.py` — new: the capture. Reads the cluster (workloads, pods, services, policies, the HelmRelease and its overlay), resolves each GitLab image's registry digest, probes the model endpoints, parses the chart templates, reconciles and renders the record.
- `charts/genieai-umbrella/values.yaml` — the source baseline: the chart defaults the deployment was rendered from.
- `charts/genieai-umbrella/templates/opea/*.yaml` — the only place that says which values key becomes which environment variable. Parsed, never guessed: a variable the parse cannot resolve is reported as TEMPLATE, not silently compared.
- `charts/genieai-umbrella/Chart.yaml` — the chart version the record compares against the deployed release.
- `docs/baselines/v03-deployed-baseline-2026-11-17.md` — the generated record (committed; regenerated by re-running the capture).

**Acceptance Criteria:**
- Given the target deployment, when the baseline is recorded, then image digests, model ids (embedding, reranker, LLM, translation), retrieval configuration values and topology are captured.
- Given the source baseline, when the capture runs, then every difference between the deployment and the source is listed with a disposition, and a difference without one fails the capture.
- Given the record, when it is read, then it carries its capture date and the command that reproduces it.

## Implementation Notes

- The baseline venue is the shared k3s `genieai` namespace (chart 0.2.177, release `genieai.v38`, external GPU model tier). PRD §13-1 (which deployment hosts the first end-to-end validation) stays open: the capture takes the namespace as an argument, so designating a venue is a re-run, not a rewrite.
- The chart source in this repository is identical to the deployed chart's source (`git diff origin/feat/k8s-migration HEAD -- charts/` is empty at version 0.2.177), so the repository's `values.yaml` is the source baseline for the deployed chart.
- The comparison layers are chart default → overlay override → running pod. A difference against the *effective* value (default + override) is a discrepancy; a difference against the chart default alone is not.
- `imageID` is the digest of the pulled image **index** (calibrated against the digest-pinned Envoy image: the pod's `imageID` equals the tag's index digest, not its amd64 child), so the registry comparison is index against index.

## Design Notes

The registry digest is resolved with an anonymous pull token; the GitLab front door answers 403 to the default Python user agent, so the capture identifies itself. The model endpoints are probed with the deployment's own TLS posture (the GPU node's certificate is signed by an internal CA, and the deployment declares `OPEA_SSL_SKIP_VERIFY=1`).

## Verification

**Commands:**
- `uv run --no-cache --with pyyaml python scripts/baseline/capture-deployed-baseline.py --namespace genieai` — expected: the record is written and the capture exits 0.
- `uv run --no-cache --with pytest --with pyyaml python -m pytest scripts/baseline/tests -q` — expected: every matrix row is covered and passing.

**Manual checks (if no CLI):**
- Read the record's discrepancy table: every row carries a disposition, none says UNRESOLVED.
- Confirm the record contains no secret value: the secret-backed rows show only `secret:<name>/<key>`.
