- (direction) David 2026-10-18: all OKF Studio features rely heavily on the local GPU; add an option to configure a REMOTE FRONTIER MODEL for the heavier administrative operations — imports' GPU operations, head tag generation, labeling during ingestion, test-suite generation, RAGAS benchmark suite generation. Embeddings, reranking, and querying STAY on the configured local GPU services.
- (direction) Config surface (David): URL, model list for selection, access token; BOTH OpenAI and Anthropic APIs must be supported; checkbox selection per OKF Studio operation choosing what delegates to the frontier model via API instead of the default hosted inference model.
- (direction) Deliverable now (David): DESIGN ONLY — a design document integrated into the feat/okf-server design work; implementation starts only after David's lookover.
- (constraint) Model-agnostic (carried from 8-6): no feature indexed on a specific frontier model; provider+model+endpoint are config, and per-operation model MINIMUMS are documented (the spec-okf-ragas-benchmarking model-requirements.md precedent).
- (constraint) Ingest-path resilience: imports must never BLOCK on the frontier model — frontier failures degrade to the local GPU model (the contextual-retrieval raw-chunk fallback precedent), loudly logged.
- (question) Scope of RAGAS delegation: David listed benchmark suite GENERATION; is run-time judge EVALUATION also delegable (equally administrative+heavy) or generation only? Recommendation: separate checkbox, default off.
- (question) Model granularity: one selected model for all delegated operations, or per-operation model choice from the fetched list? 'Model list for selection + checkbox per operation' reads like per-operation choice is wanted. Recommendation: per-operation override with a global default.
- (non-goal) NOT routed (David explicit): embeddings, reranking, querying/chat answering. Also out: translation, chat-path anything, cost metering/billing integration (observability of delegation is logged events only).
- (decision) Config storage (researched precedent): okf_system_config keyed doc _key='frontier_model' cloning retrieval-config-service (Story 1.7/ADR-okf-039 D3): joi validation at controller, optimistic concurrency (_rev), audit before/after, PUT behind requireRole('tools-admin'), env defaults merged with stored doc, redaction-on-read precedent (updated_by nulling).
- (constraint) Token secrecy HAZARD (researched): retrieval-config's audit write stores details.before/after verbatim and the Logs UI renders details — a naive clone leaks the access token into okf_audit_logs. The frontier config must mask the token in audit details AND GET responses (token_configured: true + updated_at only); DsInput type=password for the write-only field (first credential input in this frontend).
- (decision) UI placement (researched): system-level AdminDashboard tab (config is repo-independent), not inside RepoEditor/HeadTestDialog. Model picker = DsCombobox remote mode (AccessPanel group-picker precedent, debounced @search); checkboxes = native input in label (RagasPanel metrics house style; no DsCheckbox exists). Frontend role-gating is visibility-only (isAdmin pattern); true enforcement stays server-side requireRole.
- (constraint) Provider adapter contract (researched): TWO types — 'openai-compatible' (covers OpenAI/vLLM/LiteLLM/OpenRouter; base URL /v1 vs OpenRouter /api/v1 gotcha; Bearer; GET /v1/models) and 'anthropic' (x-api-key + anthropic-version 2023-06-01 two-header auth; top-level system param; max_tokens REQUIRED; temperature must NOT be sent unconditionally — newest models 400 on non-default, map cheap/fast to output_config.effort; content is typed blocks — join type=='text'; models endpoint cursor-paginated default 20, pass limit=1000, exposes max_input_tokens + capabilities).
- (decision) Strict-JSON strategy (researched): one schema-forced-JSON operation, three implementations — OpenAI response_format json_schema strict / Anthropic output_config.format json_schema (messages.parse) / vLLM json_object+guided_json — and the existing parse+retry fallback stays on ALL paths (refusal + max_tokens truncation can still yield non-compliant output). Never port prefill-'{' or forced tool_choice to Anthropic (both 400 on current models). Parse, don't regex: Anthropic emits required-keys-first order.
- (constraint) Timeouts (researched): frontier TTFT dominates for reasoning models; non-streaming requests hit ~10-min server ceilings. Labels ~120s stays fine; suite/RAGAS-generation legs 300-600s with per-leg max_tokens caps; honor Retry-After on 429 (rate limits, not GPU, govern hosted throughput). Phase-2 option: both vendors' Batch APIs (~50% cost) fit the admin-only latency-insensitive profile.
- (direction) David 2026-10-18 (context-window rule): RAGAS benchmarking (and all model routing) must STICK TO THE CONTEXT WINDOW of whatever model is selected — implemented first in ragas_engine._doc_char_cap: RAGAS_DOC_CHAR_CAP=auto derives the KG-input cap from RAGAS_JUDGE_CONTEXT_TOKENS (pair-safe: (window-3072)/2 tokens x 4 chars, clamped by RAGAS_DOC_CHAR_MAX 48000; explicit number wins, 0 disables). Frontier configs must carry the model's window the same way.
- (constraint) David 2026-10-18 (the cardinal default rule): when the external/frontier API is not configured for any feature/service — or an operation's checkbox is off — EVERYTHING defaults to the locally-configured model, exactly as today. Zero frontier config = zero behavior change; frontier is purely additive. The same defaulting applies on frontier failures (degrade to local, loudly logged).
- (note) Call-site map (researched): 9 okf-server vllmChatCompletions callers (head/tag suggest, dormant frontmatter validation, head-suite generation, head-suite explain advisor, routing advisor, routing explain, csv topic derivation, RAGAS run answer leg, RAGAS explain advisor) + 3 more Node helpers (concept-meta runLlmSummary, llm-curation callVllm [import curation/autocorrect/link-suggestions], topic-link callVllm [publish-time link authoring]); dataprep legs = labeling, contextual, graph-extraction (vendored comps LLMGraphTransformer); ragas sidecar build_llm is per-job factory (per-request override clean); dataprep ingest_file body is env-only today (per-request routing needs body extension); TEI embed/rerank + ChatQnA + translation + PII confirmed non-routable/non-LLM.
- (note) PRE-EXISTING BUG found by the map: frontmatter-service vllmChatCompletions reads container var VLLM_LLM_MODEL_ID but compose maps host VLLM_LLM_MODEL_ID to container VLLM_MODEL_ID (docker-compose.yaml:730) — every okf-server admin LLM call today sends the hardcoded granite default model string; only ragas-service and dataprep honor a configured model id. The router centralizes model resolution and fixes this.
- (note) Gift from the map: concept-meta/llm-curation/topic-link services already look up a dead config?.llm?.{endpoint,model,apiKey} block (config.js has no llm key) — a centralized llm config was already anticipated at three call sites; the router lands exactly there. Also: response_format json_object is load-bearing everywhere (Anthropic-native needs the schema-forced adapter op); timeouts span 5s-300s across sites and need per-class budgets for frontier TTFT.
- (decision) Delegation architecture: a shared okf-server llm-router service every admin LLM caller goes through — llmRouter.chat({operation, messages, maxTokens, temperature, schema?}) resolves operation->provider (frontier if configured+enabled, else local; the cardinal default rule) -> adapter (openai-compatible|anthropic) -> normalized {text, finishReason, usage}. Dataprep legs receive resolved routing per ingest request (ingest_file body extension — env-only today); graph extraction (vendored comps) stays local in v1. RAGAS sidecar takes per-request judge overrides threaded through the existing job factory.
- (direction) David 2026-10-18 (SCOPE EXPANSION, supersedes the querying/chat non-goal): the BASIC LLM INFERENCE service (chatqna answering) can ALSO delegate to the external API — 'this way the framework user can access frontier models for RAG'. So: admin AND inference operations. Embeddings + reranking still stay local (dimension-coupled to the indexed vectors — routing them breaks retrieval); translation unchanged (local, separate model).
- (decision) Propagation unification: okf-server owns the config and serves an internal GET /internal/llm-routing (internal-secret authed, like RAGAS_INTERNAL_SECRET) returning the RESOLVED per-operation routing incl. provider params; OPEA consumers (dataprep, chatqna) pull it with a TTL cache (~30-60s) and default to env/local when unreachable/unconfigured — one mechanism for all Python services, and it replaces the ingest-body-extension idea for dataprep. Streaming: chat answering must stream through the pipeline (both vendors stream SSE); the inference adapter supports streaming from v1 or the chat UX degrades — flagged as the main added risk of the expansion.
- (constraint) David 2026-10-18: the configuration screen must make it VERY CLEAR what each option does — every field and checkbox carries a plain-language explanation of its effect (the RAGAS help-panel/DsInfoTip discipline: gloss first, no jargon-only labels; each operation checkbox states what work it moves, what stays local, and the fallback behavior).
